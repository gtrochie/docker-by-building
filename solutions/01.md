# Module 01 — Solutions

**1. alpine:3.20 layer count and the big layer.**
```bash
docker pull alpine:3.20
docker history alpine:3.20
```
Alpine has essentially two rows: a `CMD` metadata layer (`0B`) and one `ADD`
layer (~7–8MB) that holds the entire root filesystem — that single layer is
basically all of the image's size.

**2. Second tag shares one IMAGE ID.**
```bash
docker tag alpine:3.20 myalpine:mine
docker images | grep -E 'alpine|myalpine'
```
Both lines show the **same IMAGE ID** — a tag is a label, not a copy.

**3. Digest of nginx:alpine + when to use it.**
```bash
docker pull nginx:alpine
docker inspect --format '{{index .RepoDigests 0}}' nginx:alpine
# nginx@sha256:...
```
Use a digest (`FROM nginx@sha256:...`) when you need a byte-for-byte reproducible
base that can never change under you — e.g. production builds and supply-chain
pinning. A tag like `:alpine` can be re-published to point at new bytes.
