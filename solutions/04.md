# Module 04 — Solutions

**1. Edit main.py, confirm pip layer stays cached.**
```bash
docker build -t freelanceforge:dev .
echo "# tweak" >> app/main.py
docker build -t freelanceforge:dev .
```
Output shows `CACHED [4/5] RUN pip install ...` and only `[5/5] COPY app/ .`
reruns — the dependency layer is untouched because requirements.txt didn't change.

**2. Wrong order reinstalls deps on every code change.**
```dockerfile
COPY app/ .                                    # source first (BAD)
RUN pip install --no-cache-dir -r requirements.txt
```
After any edit to `app/`, the `COPY app/ .` layer changes, busting the cache for
the `pip install` below it → deps reinstall every build. Revert to copying
`requirements.txt` first.

**3. Add a BuildKit cache mount.**
```dockerfile
RUN --mount=type=cache,target=/root/.cache/pip \
    pip install -r requirements.txt
```
Pip's download/build cache persists **between** builds on the host without being
baked into the image, so repeated installs (even with `--no-cache-dir` dropped)
are much faster while the image stays slim.
