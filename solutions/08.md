# Module 08 — Solutions

**1. Stack up, db/ping ok, data survives down.**
```bash
docker compose up -d --build
curl localhost:8000/db/ping           # {"db":"ok",...}
docker compose down                    # volumes kept (no -v)
docker volume ls | grep dbdata         # still present
```

**2. Dev override with bind mount + reload.**
```yaml
# compose.override.yaml
services:
  api:
    volumes: ["./app:/app"]
    command: ["uvicorn","main:app","--host","0.0.0.0","--port","8000","--reload"]
    environment: { APP_ENV: development }
```
```bash
docker compose up        # auto-merges override; edits to app/ hot-reload
```

**3. Break and restore readiness.**
```yaml
  api:
    depends_on: [db]     # start-order only -> API may hit DB too early
```
`docker compose up` may log `{"db":"error","detail":"connection refused ... db:5432"}`.
Restore the gate:
```yaml
    depends_on:
      db:
        condition: service_healthy
```
